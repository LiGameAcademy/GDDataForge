# GDDataForge 可视化编辑器设计文档

## 1. 简介与设计目标

为了简化 GDDataForge 插件的工作流程，提升用户体验，我们计划设计并开发一个集成的可视化数据编辑器。该编辑器将内嵌于 Godot Editor 中，允许用户通过图形化界面管理和编辑所有游戏数据，而无需直接操作文件系统或手动编写资源配置。

### 核心设计目标

- **简化工作流**：实现数据表（`TableType`）、数据模型（`ModelType`）与数据文件（CSV/JSON）的自动化创建与关联。
- **可视化操作**：提供一个直观、高效的类电子表格界面，用于查看、编辑、添加和删除数据。
- **实时验证**：在编辑过程中，根据 `ModelType` 的定义对数据进行实时类型检查和有效性验证，提供即时反馈。
- **自动化管理**：在后台自动处理文件的读取、写入、Godot 资源的更新以及与 `DataManager` 的同步。

## 2. UI 布局与核心组件

编辑器将作为 Godot 编辑器的一个主屏幕停靠面板（或底部面板），命名为 **"DataForge"**。该面板将整合所有与数据管理相关的功能，并由以下三个核心组件构成：

### 2.1. 数据表列表 (Data Table List)

- **位置**: 面板左侧。
- **功能**:
    - 以可搜索的树状/列表形式，展示项目中 (`res://`) 所有的 `TableType` 资源。
    - 提供上下文菜单或工具栏按钮，用于 **创建新数据表**、**删除选中表**、在文件系统中 **定位资源**。
    - 可选：通过状态图标（如 `●` `○` `*`）标示数据表的同步状态（已同步、未加载、有未保存的更改）。

### 2.2. 表格配置与模型视图 (Configuration & Model View)

- **位置**: 面板右侧或顶部。
- **功能**: 当用户在左侧列表中选择一个数据表时，此视图将显示其详细配置。
    - **TableType 配置**:
        - **表名 (ID)**: `TableType` 的唯一标识符。
        - **数据源文件**: 显示并允许修改关联的 `.csv` 或 `.json` 文件路径。
    - **ModelType 配置**:
        - **模型脚本**: 显示并允许创建或关联一个新的 `ModelType` 脚本（`.gd`）。
        - **字段映射**: 展示数据列与模型脚本中导出变量的对应关系。理想情况下应自动检测，但也支持手动调整。

### 2.3. 数据网格编辑器 (Data Grid Editor)

- **位置**: 中央主区域。
- **功能**: 编辑器的核心，提供一个强大的电子表格界面。
    - **表头**: 显示数据文件的列名，支持点击排序。
    - **数据行**: 每一行对应一条数据记录。支持右键添加/删除行。
    - **智能单元格编辑**:
        - 根据 `ModelType` 中定义的变量类型，提供定制化的编辑器：
            - `String`, `int`, `float`: 标准文本输入框。
            - `bool`: 复选框 (Checkbox)。
            - `enum`: 下拉选择列表。
            - `Resource` 类型 (如 `Texture2D`, `AudioStream`): 资源拖放框或弹出式资源选择器。
            - `Color`: 颜色选择器。
    - **实时数据验证**: 若输入数据与模型类型不匹配，单元格将高亮（如红色边框）并提供错误提示。
    - **工具栏**:
        - **保存**: 将网格中的所有更改写回到数据源文件。
        - **重新加载**: 放弃更改，从文件重新加载数据。
        - **添加/删除行/列**: 快速修改数据结构。修改列会直接影响关联的 `ModelType` 脚本。
        - **导入/导出**: 支持从外部 CSV/JSON 文件导入数据或导出当前数据。

## 3. 典型用户工作流

1.  **启动**: 用户在 Godot 中打开 "DataForge" 面板。
2.  **创建**: 用户点击 "创建新数据表" 按钮。
3.  **向导**: 一个配置向导出现，引导用户完成以下步骤：
    a. **定义数据表**: 输入表名 (ID，如 "items")，选择数据格式 (CSV/JSON)，并指定文件名 (如 `items.csv`)。
    b. **定义数据模型**: 创建一个新的 `ModelType` 脚本 (如 `item_model.gd`)。编辑器会自动生成一个包含 `extends Resource` 的基础脚本。
4.  **编辑结构**: 创建完成后，DataForge 会显示一个空的网格。用户通过 "添加列" 按钮定义数据结构。每添加一列（如 "name"），编辑器会自动在 `item_model.gd` 脚本中追加一行 `@export var name: String`。用户可以为每一列指定数据类型。
5.  **编辑内容**: 用户在网格中填入具体的物品数据。
6.  **保存**: 用户点击 "保存" 按钮。此时，插件执行以下操作：
    a. 将网格中的数据写入 `items.csv` 文件。
    b. 保存 `TableType` 和 `ModelType` 资源文件。
    c. 可选：自动通过 `DataManager` 重新加载该表的数据。
7.  **使用**: 开发者可以在游戏的任何脚本中，通过 `DataManager.get_data_model("items", "item_id")` 来安全、方便地获取刚刚创建的数据模型实例。

## 4. 未来扩展

- **高级数据验证**: 允许用户在 `ModelType` 中定义更复杂的验证规则（如范围、正则表达式）。
- **数据筛选与搜索**: 在数据网格编辑器中提供强大的数据筛选和文本搜索功能。
- **多语言支持 (i18n)**: 为数据表的本地化提供特殊支持。
- **数据库集成**: 支持直接连接和编辑 SQLite 或其他轻量级数据库。
