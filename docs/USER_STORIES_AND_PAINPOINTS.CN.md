# GDDataForge 用户故事与痛点分析（产品需求文档）

## 1. 文档目的

本文件用于回答三个问题：

- 用户真正需要什么？
- 全能数据编辑器应该具备哪些能力？
- 迭代优先级应该如何排序？

本文档与以下文档配套使用：

- `UNIFIED_DATA_PIPELINE_ARCHITECTURE.CN.md`
- `EDITOR_VS_RUNTIME_DECISION.CN.md`

## 2. 目标用户分层

### 2.1 策划（主要用户）

关注点：

- 快速改表、批量改值、少出错。
- 改完能立即验证并看到结果。
- 不依赖程序也能完成绝大部分配置工作。

### 2.2 程序（平台维护者）

关注点：

- 单一数据管线，避免双逻辑维护。
- 数据结构可演进（加列、改名、迁移）。
- 运行时加载稳定、性能可控、可调试。

### 2.3 技术美术/关卡（高频协作者）

关注点：

- 资源字段（图标、音频、Prefab）可视化编辑。
- 与 Godot 资源系统联动顺滑。
- 快速定位错误字段和缺失资源。

### 2.4 QA / 运营 / GM（可选用户）

关注点：

- 能否在运行时快速验证或修正配置。
- 修改行为可追踪、可回滚、可审计。

## 3. 用户真正需要的核心价值

按价值排序：

1. **正确性**：数据不会“看起来改了，实际没生效”。
2. **效率**：高频批量改表操作足够快。
3. **一致性**：编辑器与运行时结果一致。
4. **协作性**：多人改表可合并、可审查、可追溯。

## 4. 典型用户故事（User Stories）

### 4.1 策划故事

- 作为策划，我希望批量调整某字段并立即预览校验结果，以便快速完成版本平衡。
- 作为策划，我希望保存后自动重载并刷新显示，以确认改动已落盘且可用。
- 作为策划，我希望新增字段时自动填充默认值并提示受影响记录。

### 4.2 程序故事

- 作为程序，我希望编辑器和运行时共享同一解析/序列化模块，以避免行为分叉。
- 作为程序，我希望新增自定义数据格式时只需注册 Adapter，而不改编辑器主流程。
- 作为程序，我希望能一键执行全表校验并输出机器可读报告（CI 可接入）。

### 4.3 技术美术故事

- 作为技术美术，我希望纹理/音频字段可以直接选择资源并预览，而不是手填路径。
- 作为技术美术，我希望能快速找出失效资源引用并一键定位。

### 4.4 QA/运营故事（可选）

- 作为 QA，我希望在 Debug 运行时快速查表与改单值并回滚。
- 作为运营，我希望变更有权限控制和审计日志，避免误操作上线。

## 5. 当前痛点与根因

### 5.1 痛点列表

- 保存、刷新、缓存状态偶发不一致。
- 弹窗节点路径脆弱，容易出现 null 报错。
- 高复杂 UI（冻结区/联动）引入大量显示与交互问题。
- 编辑器与运行时存在双维护趋势。
- 数据结构变更（字段改名/删除）缺少影响分析与迁移护栏。

### 5.2 根因

- UI 层承担了过多数据语义职责。
- 统一中间模型与统一仓储层尚未完全落地。
- 缺少“产品级护栏”：保存前校验、快照回滚、差异确认。

## 6. 全能数据编辑器能力模型

### 6.1 L1 必须有（MVP）

- 稳定打开/保存/重载
- 单元格编辑、行列增删改
- 基础校验（必填/唯一/类型）
- 导入导出（CSV/JSON）
- 清晰错误提示（定位到字段/行）

### 6.2 L2 高价值（应尽快）

- 批量操作（筛选、批量替换、批量填充）
- 结构迁移助手（改名/删字段影响提示）
- 引用分析（外键、资源引用）
- 自动快照与回滚

### 6.3 L3 专业化（后续）

- 自定义加载器市场化注册
- CI 校验流水线集成
- 运行时调试编辑器（Debug only）
- 审计日志与权限系统（面向线上）

## 7. 文本配置 vs Resource 配置（用户视角）

### 7.1 用户体验结论

- 对协作与版本管理：文本配置更友好。
- 对 Godot 集成与类型安全：Resource 更友好。

最佳实践：

- **文本为真源（Source of Truth）**
- **Resource 为投影（Projection）**

即：用户编辑文本语义数据，系统在构建或运行时生成/缓存 Resource。

## 8. 需求优先级（建议）

### P0（立即）

- 统一数据管线核心骨架（Adapter + Document + Repository）
- 编辑器读写切到 Repository
- 保存后自动重载与状态一致性
- 表单节点查找健壮化（彻底移除硬编码路径依赖）

### P1（近期）

- 批量打开目录、批量编辑工具
- 字段迁移助手（改名/删除影响提示）
- 引用检查与失效资源扫描

### P2（中期）

- Runtime Debug Editor（仅 Debug）
- 自定义加载器注册 UI
- CI 校验报告导出

## 9. 成功指标（KPIs）

- 数据编辑相关报错率下降（Null/Node not found 类）。
- 保存后重载一致性问题归零。
- 新增格式接入工时下降（仅新增 Adapter）。
- 策划高频改表效率提升（操作步数、完成时长）。
